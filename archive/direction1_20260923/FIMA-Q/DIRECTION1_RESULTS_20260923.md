# 创新点 1：首轮结果分析（2026-09-23）

## 结论

本轮没有观察到准确率提升。adaptive 相对 monitor 的 Top-1 低 0.052 个百分点，总耗时少 15 分 21 秒（10.435%）。但 adaptive 没有触发任何初始化之后的 Fisher 更新，因此尚不能证明可靠性调度机制有效。结果提示低秩方向数/估计频率存在压缩空间，仍需低预算固定基线验证。

## 数据来源与配置核验

- monitor：`checkpoints/quant_result/20260922_201308_direction1_monitor_seed3407/`
- adaptive：`checkpoints/quant_result/20260922_224018_direction1_adaptive_seed3407/`
- 两组均完整结束，recon_iters=20000，不是 100 步冒烟实验。
- 两份 experiment.json 的 config 完全相同，args 仅 fisher_schedule 不同。
- 两份 probe_split.json 一致：960 张重构、64 张探针，共 1024 张训练校准池。
- ViT-S，W4A4（patch embedding 激活按原配置为 8 bit），seed=3407，k=15，QDrop=0.5，temperature=20。
- 探针每 500 步检查一次，误差增量阈值 0.25，反向趋势阈值 0.02，连续异常次数 2。
- checkpoint 路径相同；日志未保存 checkpoint 哈希、图像张量哈希和服务器代码版本，无法据此证明实际输入逐位相同。

## 为什么没有触发

当前规则检测的是相对误差 E 相对初始化锚点 E0 的增量，不是 E 本身是否很大：E > E0 + 0.25。

adaptive 各单元最大 E-E0 为：

| 单元 | 最大误差增量 |
|---|---:|
| patch_embed | 0.13029 |
| blocks.0 | 0.12626 |
| blocks.1 | 0.01248 |
| blocks.2 | 0.18987 |
| blocks.3 | 0.14860 |
| blocks.4 | 0.15391 |
| blocks.5 | 0.20843 |
| blocks.6 | 0.01878 |
| blocks.7 | 0.10303 |
| blocks.8 | 0.09709 |
| blocks.9 | 0.07425 |
| blocks.10 | 0.00451 |
| blocks.11 | 0.09649 |

全部小于 0.25，所以 error_bad 一次也没有发生。8 次 trend_bad 分布于 blocks.0（2000、3000、4000、7500 步）、blocks.1（2000）、blocks.2（1500）、blocks.4（1500）、blocks.5（2000），没有同一单元连续两次异常，因此 trigger 全为 false。这是按现有规则运行的结果，不是更新分支报错。

最终低秩分量只有一个方向，同时仍保留对角分量，应称为“单方向低秩分量 + 对角项”，而非完整 Fisher 为 rank-1。保存文件名中的 rank_15 只是配置参数，不能作为最终实际秩证据。

## 需要承认的方法限制

1. 首版阈值没有依据本任务的探针噪声做标定。在本轮轨迹上，0.25 高于所有误差增量，因而未激活更新。
2. 高锚点误差可掩盖“从一开始就拟合较差”的状态。例如 adaptive 的 patch_embed 锚点 E0=0.82057，阈值约 1.07057，最大 E 约 0.95086。不能把“不触发”解释为“Fisher 很准确”。E 不是相关系数，也不是分类错误率。
3. 探针评估的是关闭 QDrop、FP 前缀/后缀、当前块 soft-round 的局部状态；训练还包含量化输入混合，部署使用 hard-round。局部探针无法完整代表误差累积及最终准确率。
4. 两组 patch_embed 在 step=0 的初始 KL 分别为 1.40704e-5 和 1.43067e-5，锚点误差分别为 0.79332 和 0.82057，此时还没有发生不同的更新调度。说明初始统计并非完全一致，值得检查数据/运行确定性。
5. 当前 seed_all 只设置 NumPy/PyTorch/CUDA seed，没有设置 Python random.seed；数据通过 is_training=True 的随机增强直接预加载。Python 随机增强是潜在差异来源，但仅凭日志不能断言它就是唯一原因。下一轮应固定全部随机源并共享缓存图像张量，记录哈希和环境/代码版本。

## 下一步建议（本次没有修改训练算法）

优先补充相同 960/64 划分下的 monitor --k 1 对照。它只初始化一次 Fisher，不依赖触发决策，可以检验本轮收益是否完全来自少估计 Fisher。该对照必须与 adaptive 使用相同缓存张量和随机状态，不能直接拿历史 1024 张数据的基线替代。

在公平性固定后，如果单方向基线与 adaptive 一致，本轮应归类为减少校准成本的线索，而不是自适应精度提升。若继续以准确率为目标，需要先建立更能反映真实量化输入/硬舍入的失配证据。

不建议为了让模块触发而盲目降低阈值。可以在独立开发校准数据上标定噪声尺度，分析失配是否预测未来 KL 恶化，再冻结阈值做正式比较；改变阈值后必须重跑，不能从现有日志推断反事实精度。

目前不宜同时大改多个模块或直接扩大到多模型大规模实验。先确定方法是否比固定单次更新有独立收益，再进行多种子/W3A3 扩展。
